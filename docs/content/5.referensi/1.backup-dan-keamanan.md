Keamanan hasil ujian dan ketahanan data lokal merupakan prioritas utama pada arsitektur **NILUJI**.

## Pencadangan Otomatis

NILUJI menyimpan tiga jenis cadangan di subdirektori `backups/`:
1. **Harian** (`cbt-harian-YYYY-MM-DD.sqlite`): dibuat saat aplikasi dibuka, diperbarui tiap jam selama aplikasi berjalan, dan disimpan untuk **14 hari pemakaian**.
2. **Manual** (`cbt-backup-*.sqlite`): dibuat lewat tombol **Backup Sekarang**, disimpan hingga 14 berkas terakhir.
3. **Sebelum perubahan** (`cbt-sebelum-*.sqlite`): dibuat otomatis sebelum reset sesi, nilai ulang, hapus ujian, hapus mata pelajaran, dan pemulihan, disimpan hingga 5 berkas terakhir.

Gambar soal ikut disalin ke `backups/uploads/`.

### Cara Memulihkan (*Restore*) Database dari Cadangan:
1. Pastikan tidak ada siswa yang sedang mengerjakan ujian.
2. Buka **Tentang > Fitur**, lalu cari kartu **Backup Database**.
3. Pilih cadangan pada **Pulihkan dari backup**, klik **Pulihkan**, lalu konfirmasi.

Kondisi data sebelum pemulihan disimpan otomatis sebagai cadangan **Sebelum perubahan**, sehingga pemulihan yang keliru masih bisa dibatalkan.

Untuk memindahkan data ke komputer lain, tutup NILUJI, salin satu berkas cadangan ke folder data aplikasi sebagai `cbt.sqlite`, lalu salin isi `backups/uploads/` ke folder `uploads/`.

## Ringkasan Lapisan Keamanan Ujian

| Lapisan Proteksi | Cara Kerja di NILUJI |
| :--- | :--- |
| **Timer Berbasis Server (*Server-Relative Timer*)** | Sisa waktu ujian dihitung dari selisih waktu server (`started_at + duration + extra_minutes - server_now`). Mengubah jam pada pengaturan HP/laptop siswa tidak memengaruhi sisa waktu ujian. |
| **Penolakan Jawaban Saat Waktu Habis** | Endpoint `/api/exam/answer` di server Rust memeriksa batas waktu sesi secara ketat. Jawaban yang dikirim melewati batas waktu ujian (+ *grace period* toleransi jaringan) otomatis ditolak. |
| **Kunci Satu Perangkat (*Single-Device Lock*)** | Saat siswa memulai ujian, sesi diikat pada `device_token` unik perangkat tersebut. Login dari perangkat kedua akan diblokir kecuali pengawas menekan tombol **Buka Kunci Perangkat**. |
| **Token Sesi Rahasia** | Server memberi token acak saat siswa masuk. Jawaban dan pengumpulan tanpa token sesi tersebut ditolak, sehingga siswa tidak dapat mengubah ujian siswa lain. |
| **PIN Peserta 6 Digit** | Aktif secara bawaan pada ujian baru. Mencegah siswa memakai NISN teman sekelasnya tanpa memegang fisik Kartu Peserta Ujian. |
| **Pembatasan Percobaan** | Login, token, dan PIN yang berulang kali salah diblokir sementara per perangkat. |
| **Pembatasan Kelas** | Siswa hanya dapat masuk ke ujian untuk kelas tempat ia terdaftar. |
| **Salinan Soal per Sesi** | Soal, kunci, dan skor disalin saat sesi dimulai, sehingga perubahan Bank Soal tidak mengubah hasil yang sudah ada. |
| **Acak Opsi & Soal Deterministik** | Urutan soal PG, opsi A-D, dan soal Esai diacak menggunakan *hash seed* `(session_id, question_id)`. Urutan opsi pada layar siswa tetap stabil saat halaman di-*refresh*, namun berbeda antar-siswa yang duduk bersebelahan. |
| **Pengumpulan Otomatis** | Sesi yang ditinggalkan siswa dikumpulkan server 3 menit setelah waktunya habis. Pengawas dapat membukanya kembali dengan tambahan waktu. |
| **Validasi Berkas & CSP** | Perintah baca/tulis berkas hanya menerima ekstensi yang diizinkan, pemuat gambar hanya membaca folder `uploads`, dan aplikasi desktop tidak menjalankan skrip inline yang tidak dikenal. |
